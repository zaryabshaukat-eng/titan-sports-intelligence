# TITAN OS v0.3.0 Staging Release Notes

## Included

- Canonical provider-neutral Sports Domain.
- Auditable Fixture, Market Data/Odds, and Statistics ingestion.
- Immutable historical observations, checksums, idempotency, audits, migrations, and transactional outboxes.
- Local lease-based outbox worker with retries and dead-letter evidence.
- Pluggable development/JWT identity foundation with RBAC.
- Liveness/readiness, Prometheus metrics, structured logs, correlation IDs, and CI validation.

## Excluded

Feature engineering, research, machine learning, probabilities, consensus, risk, recommendations, and backtesting are intentionally not in v0.3.0.

## Deployment and rollback checklist

1. Verify secrets, CORS, TLS/ingress, managed PostgreSQL/Redis, backups, and alert routing.
2. Run CI including PostgreSQL integration validation and review coverage artifacts.
3. Back up the target database; run `alembic upgrade head`; deploy API and worker; verify `/health`, `/ready`, and `/metrics`. Docker Compose runs this migration step through `migrate` and blocks API/worker startup until it succeeds.
4. Roll back the application image first. Downgrade a migration only when its reviewed rollback is safe and a verified backup exists.
